# Readable JSON export — scoped verification

Date: 2026-10-15, America/Sao_Paulo. Scope: the user's readable-export follow-up only. **This does not reassess or change Stage 2 acceptance; its recorded overall status remains FAIL.**

## Behavior and compatibility

DATA_CONTRACT requires compact default export and already permits a separate pretty variant. **Export JSON** retains its byte-exact compact behavior. **Export readable JSON** is available in the toolbar and saved-workflow manager, using two spaces per level and LF line breaks. It adds whitespace directly to validated canonical tokens, preserving integer-like/Unicode key ordering, node/edge IDs, configurations, payload arrays, string escapes and schema-v1 fields. Existing negative-zero JSON normalization is unchanged.

The readable variant is checked against the same 5 MiB raw import limit, including formatting whitespace. At the exact cap it exports/imports successfully; at cap + 1 it returns a resource error without a download. Compact export remains available; no data is truncated or silently substituted. Both options use existing draft resolution and object-URL cleanup. Export does not mark browser storage Saved.

Canonical serialization, encodeDocument, the IndexedDB adapter, dependencies, QUALITY_GATES and STAGE_2_REPORT were verified byte-identical before/after this fix. Hashes and internal persistence continue to use compact bytes. Import retains the established import-as-new identity/timestamp behavior, preserving graph content and endpoint topology. [Decision D-20](../DECISIONS.md) and the affected data/schema/persistence/UI contracts document the additive option; no migration is introduced.
